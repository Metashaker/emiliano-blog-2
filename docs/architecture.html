The Laws · Invariants that hold in every phase

Six rules we never break

  • I
    Gate on the server.Premium HTML never reaches a non-member. No hiding paid text with CSS.
  • II
    Canonical everywhere.Every syndicated copy points back to Aether. The blog is always the original.
  • III
    Rails is the identity provider.Auth issues verifiable tokens, never cookies-only — so products can trust it later.
  • IV
    Ghost stays vanilla.Custom billing, auth, and syndication live in Rails — never as Ghost forks.
  • V
    One entitlement contract.Astro and every AI product ask the same Rails endpoint. Logic is never duplicated.
  • VI
    Modular monolith.One Rails app, clean domains — so services extract cleanly when scale demands.

The Ascent · Three phases, in order

Build sequence

Each phase ships something usable. Nothing in an early phase blocks a later one, because the boundaries were drawn up front.

Phase 1 · Foundation

Free bilingual blog + syndication

A fast, beautiful es/en blog reading from Ghost that auto-syndicates new posts with canonical URLs. No auth, no payments.

Deliver

  • Astro site from Ghost Content API
  • i18n routing, switcher, localized RSS
  • Space-Greek design system + starfield
  • Rails syndication domain + adapters
  • Publish webhook → rebuild + fan-out

Done when

  • Publishing → live + syndicated, zero manual steps
  • Edits re-sync as updates, no duplicates
  • Readable with JS disabled; a11y ≥ 95

Phase 2 · Membership

Stripe subscription + gated posts

Some posts go premium. Only paying members receive their content — billing truth in Stripe, gate enforced by a Rails entitlement check.

Deliver

  • Rails Identity (token auth, IdP)
  • Rails Billing + Stripe Entitlements + webhooks
  • /api/v1/entitlements contract
  • Astro hybrid SSR gating
  • Teaser + paywall + Customer Portal

Done when

  • Anon request returns only teaser HTML on the wire
  • Checkout grants access with no redeploy
  • Cancel revokes per Stripe state

Phase 3 · Constellation

Shared identity across AI products

Other products authenticate against Rails and honor the same subscription — no new billing, no new login.

Deliver

  • Rails as OAuth2 / OIDC provider
  • Versioned entitlements API, per-product keys
  • Central login, refresh, revocation
  • Product onboarding docs

Done when

  • One login recognized across blog + product
  • One subscription unlocks posts + product features
  • New product = registration + checks only
